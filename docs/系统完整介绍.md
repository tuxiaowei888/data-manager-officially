## 一、系统概述

**数维数据管家系统**是一个 SaaS 化的数据资产评价系统。核心价值是：用户填写数据资产调查表单后，系统通过预置的专家规则库自动计算得分、判定风险等级、检索政策知识库，并可选调用 AI 大模型生成专业诊断报告。

**一句话定位**：帮助企业评估数据资产成熟度，从"合规"到"入表"再到"融资/交易"的全链路解决方案。

**核心设计理念**：规则库评分 → 知识库碰撞 → AI 整体出报告

```
第一段：规则库评分     →  31条规则计算，输出8维度得分
第二段：知识库碰撞     →  向量检索+静态库，输出政策建议
第三段：AI整体出报告   →  三要素融合，输出7章诊断报告
```

**当前版本**：V2.0（开发中，完成度约 75%）

### 2.3 核心请求流程（三段式）

```
用户填写表单
    ↓
API: POST /api/v1/evaluation/evaluate
    ↓
EvaluationService.evaluate()
    ├── Step 1: _prepare_eval_data()     → 转换表单字段
    ├── Step 2: _calculate_with_rules()  → 规则库评分（31条规则）
    ├── Step 3: knowledge_engine.collide() → 知识库碰撞（两层检索）
    ├── Step 4: _call_ai_api()           → AI 三要素融合生成报告
    └── Step 5: _generate_report()        → 整合输出 + 持久化
    ↓
返回完整评估报告（含8维度得分、风险等级、问题清单、AI报告）
```

**三段式核心设计**：
- **第一段（规则库评分）**：SimpleEval 安全表达式求值，输出 8 维度得分
- **第二段（知识库碰撞）**：ChromaDB 向量检索 + PolicyRetriever 静态库，输出政策建议
- **第三段（AI整体出报告）**：三要素融合（用户数据 + 规则评分 + 知识库政策），输出 7 章诊断报告

## 四、评估引擎详解

### 4.1 八大评估维度

| 代码 | 维度名称 | 权重 | 规则数 | 评估重点 |
|------|---------|------|--------|---------|
| C | 合规与安全 | 20% | 7条 | 数据来源合法性、隐私保护、安全措施 |
| Q | 数据质量 | 15% | 4条 | 完整性、准确性、标准化 |
| O | 权属确认 | 15% | 4条 | 权属、使用权、收益权、独创性 |
| V | 价值评估 | 20% | 4条 | 应用场景、变现能力、数据规模 |
| M | 管理体系 | 10% | 3条 | 治理组织、管理制度、质量监控 |
| L | 流通能力 | 10% | 3条 | 共享能力、API服务、交易记录 |
| P | 发展潜力 | 5% | 3条 | 增长趋势、技术创新、市场拓展 |
| S | 成本计量 | 5% | 3条 | 成本核算、存储成本、运维成本 |

### 4.2 规则计算流程

1. 从 `rule_configs` 表加载所有 `is_active=True` 且 `is_deleted=False` 的规则
2. 对每条规则，使用 `RuleCalculator.calculate_single_rule()` 执行 `logic_expression`
3. 表达式通过 `simpleeval` 安全求值，支持 min/max/sum/len 等内置函数
4. 未定义变量自动赋默认值 0，避免运行时错误
5. 结果归一化到 0-1 范围，再乘以 100 得到百分制分数
6. 按维度聚合：加权平均得到维度分，再按维度权重加权得到总分

### 4.3 规则表达式示例

```python
# 合规与安全 - 数据来源合规性
"len([x for x in data_source if x in ['用户授权协议', '政府公开数据', '合法购买']]) / max(len(data_source), 1) * 100"

# 数据质量 - 元数据完整性
"completeness"

# 权属确认 - 数据权属确认
"100 if '数据资产登记证书' in rights_cert else (60 if '知识产权登记证书' in rights_cert else (30 if '政府授权运营书' in rights_cert else 0))"

# 价值评估 - 数据规模价值
"100 if data_volume_records == '千万级以上' else (80 if data_volume_records == '百万级' else (50 if data_volume_records == '十万级' else 20))"
```

### 4.5 问题分级

- **P0 阻断性问题**：触发合规红线（如敏感数据明文存储、用户授权缺失、权属凭证真空），禁止交易/入表
- **P1 减值性问题**：影响估值（如数据质量缺陷，成本归集缺失），需要整改
- **P2 优化性问题**：建议改进（如产品形态单一），提升价值

### 4.6 核心理念：规则库评分 → 知识库碰撞 → AI 整体出报告

### 5.3 报告结构（7章）

### 6.1 四档订阅层级

|------|------|---------|---------|--------|---------|---------|

| 基础版 basic | ¥4,980 | 5次/年 | diagnosis | 10个 | 3个 | 1年 |
| 专业版 pro | ¥16,800 | 20次/年 | action_plan | 50个 | 无限 | 2年 |
| 企业版 enterprise | ¥49,800起 | 不限量 | full | 无限 | 无限 | 永久 |

### 6.2 报告深度控制

| 深度 | 包含内容 | 锁定内容 |
|------|---------|---------|
| summary | 总分、风险等级、总体评估 | 维度分析、行动方案、多数据集 |
| diagnosis | +维度详细分析、风险详情、改进建议 | 行动方案、多数据集 |
| action_plan | +路径推荐、价值预测、实施路线图 | 多数据集 |
| full | +多数据集概览、品牌定制 | 无 |

### 6.3 客户分层系统

基于 5 个信号维度计算客户价值：

| 信号 | 权重 | 计算依据 |
|------|------|---------|
| 活跃度 activity | 25% | 近30天评估频率 |
| 价值深度 value_depth | 25% | 总评估次数 + 平均分 |
| 产品广度 product_breadth | 20% | 数据集/档案使用 + 订阅层级 |
| 忠诚度 loyalty | 20% | 注册时长 + 最近评估间隔 |
| 升级潜力 upgrade_potential | 10% | 免费用户高频使用 = 高潜力 |

分层结果：
- **high_value**（综合分≥70 且活跃度≥60 且价值深度≥60）：专属客户经理
- **nurturing**（综合分≥40）：引导升级转化
- **observer**（综合分<40）：激活引导

### 6.4 旧 VIP 兼容策略

- 旧 `is_vip=True` 且未过期的用户，自动映射为 `basic` 层级
- `effective_subscription_tier` 属性优先使用 `subscription_tier`，回退到 VIP 判断
- `vip_expire_date` 字段复用为订阅过期日期

## 九、安全设计

### 9.1 认证与授权

- **JWT 令牌**：HS256 算法，7天有效期
- **密码哈希**：bcrypt 加盐哈希
- **SECRET_KEY**：必须从环境变量读取，生产环境强制校验
- **管理员检查**：`check_admin()` 依赖注入，验证 `user_type == 'admin'`

### 9.2 数据库安全

- **连接池**：pool_pre_ping=True，连接前检查有效性
- **事务回滚**：get_db() 中 except 块自动 rollback
- **软删除**：数据集/企业档案有关联记录时使用软删除

### 9.3 规则引擎安全

- **SimpleEval**：安全表达式求值，禁止任意代码执行
- **未定义变量**：自动赋默认值 0，避免 NameError
- **二次降级**：simple_eval 失败后尝试 EvalWithCompoundTypes
